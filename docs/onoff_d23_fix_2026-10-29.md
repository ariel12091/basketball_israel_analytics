# On/Off D23 repair, 2026-10-29

OFF keeps the current season-view definition, including team games before a
player's first appearance. No metric definition or UI layout changed.

## Database repair

`scripts/repair_onoff_d23.R` defaults to a rolled-back trial. `--apply` refreshes
`player_four_factors_by_game` in five-game batches and advances the existing
`app_meta.etl_full_last_success` cache version after successful validation.
Uses `etl/.Renviron`, port 5432, and the existing refresh function; no DDL.

The trial and committed repair covered **47 distinct 2027 games** (94 team-game
schedule rows). Refresh time: about 26 seconds in the final trial, 33 seconds
when committing batches. Rows: 83,404 -> 83,798; 420 added or changed versions,
26 removed or replaced versions. **No ON rows changed.** Summary and both Four
Factors readers now match the season views under the nightly pin's tolerances.

## Prevention

`etl/onoff_roster_refresh.R` snapshots `(season, team, player)` lookup membership
before importing games. If a team gains a player, Phase 4 refreshes its historical
games as well as the new games. Other incremental readers keep their usual game
set. A historical missing-coverage check also recovers after a failed Phase 4,
when the new lookup membership has already been committed. It ignores missing
coverage in games already due for the ordinary refresh.

Only the Israeli pipeline calls this helper. EuroLeague/EuroCup use their own
loader and are outside D23's affected tables.

Tests: `test-onoff-roster-refresh.R` covers roster growth, existing players,
transfers, season/team isolation and game deduplication.
`test-onoff-roster-refresh-db.R` uses temporary relations to exercise the actual
SQL retry planner and the ordinary incremental path. Both pass (nine assertions).
The existing `test-player-reader-paths-db.R` passes **96/96 assertions** as
`app_readonly`, covering both 2026 and 2027, including the formerly failing checks.

Production uses `main`. Apply only this repair's diff to it; do not merge the
historical `sql/web-foundation` branch or its publication/loader changes.
